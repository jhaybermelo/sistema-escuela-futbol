# Backend (FastAPI + SQLAlchemy async + Postgres)

Read `CLAUDE.md` at the repo root first for the full architecture (layering rules, billing engine, receipts, scheduler, role scoping) and the Docker-networking gotcha (use `localhost`, not `127.0.0.1`, from the host). This skill covers the day-to-day mechanics.

## Start it

```bash
docker compose up -d postgres-db backend
curl -s http://localhost:8000/api/health
```
The backend container runs `uvicorn --reload` with `./backend:/app` bind-mounted, so edits to `backend/app/**` take effect immediately — check `docker logs escuela-futbol-backend --tail 30` after a save to confirm it reloaded cleanly before testing.

## Add a new resource

Mirror an existing chain end-to-end rather than improvising a new pattern — `alumnos` (simple CRUD + a service for cross-entity logic) and `mensualidades` (admin-only, router-level `require_admin`) are the two reference examples.

1. **Model** (`app/models/<resource>.py`) — `Mapped`/`mapped_column`, add it to `app/models/__init__.py`'s imports (this is also alembic's autodiscovery entrypoint).
2. **Schema** (`app/schemas/<resource>.py`) — `*Create`/`*Update` (all fields optional)/`*Response` (`model_config = {"from_attributes": True}`)/`*ListResponse{items,total,page,size,pages}`.
3. **Repository** (`app/repositories/<resource>_repository.py`) — takes `db: AsyncSession`, all query logic, **no commits**. Add `from __future__ import annotations` at the top (a method named `list` shadows the `list` builtin for any later same-class method's `list[...]` return annotation otherwise — a real bug that has bitten this codebase before).
4. **Service** (`app/services/<resource>_service.py`) — only if there's real cross-entity business logic; it owns the commit. Skip this layer for plain CRUD.
5. **Router** (`app/routers/<resource>.py`) — mount in `app/main.py` via `app.include_router(<resource>.router, prefix="/api")`. Use `dependencies=[Depends(require_admin)]` at the `APIRouter(...)` level if the whole resource is admin-only.
6. **Migration**:
   ```bash
   docker exec escuela-futbol-backend alembic revision --autogenerate -m "add_<resource>"
   ```
   Open the generated file before applying. If you're adding a `NOT NULL` and/or `UNIQUE` column to a table that may already have rows, the autogenerated migration will fail on real data unless you add a `server_default` (a fixed string default for a `UNIQUE` column will collide — use `sa.text('gen_random_uuid()::text')` for that case). Then:
   ```bash
   docker exec escuela-futbol-backend alembic upgrade head
   ```

## Verify before wiring the frontend

Get a token and exercise the new endpoints directly — this has consistently caught bugs (route-ordering shadowing a `/{id}` path, missing `selectinload`, a bad migration default) faster than testing through the UI:
```bash
TOKEN=$(curl -s -X POST http://localhost:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@escuela.com","password":"admin123"}' \
  | python -c "import sys,json; print(json.load(sys.stdin)['access_token'])")
curl -s http://localhost:8000/api/<resource> -H "Authorization: Bearer $TOKEN"
```
If you add a route with a literal path segment (e.g. `/resumen-cartera`) on a router that also has a `/{id}`-style route, register the literal-segment route **before** the dynamic one, or the dynamic route will greedily match it and fail type validation instead of falling through.

## Common pitfalls specific to this codebase

- **Async relationships**: nothing lazy-loads. Any relationship you read after the query returns must be in a `selectinload(...)` (nest with `.selectinload(...)` for relationships-of-relationships), or you get `MissingGreenlet`.
- **Stale identity map**: if you mutate related rows (bulk delete/insert) mid-request and then need an up-to-date aggregate on an already-loaded object, re-query the aggregate directly rather than trusting the ORM relationship collection — see `marcar_pagado`/`marcar_pendiente` in `routers/mensualidades.py` for the pattern.
- **No test suite** — verification is manual curl + `docker logs`. Don't invent a pytest suite unasked; match the existing verification style.
- Only run more than one backend worker/replica if you also change the scheduler design — `core/scheduler.py`'s APScheduler jobs assume a single process and will double-fire otherwise.
